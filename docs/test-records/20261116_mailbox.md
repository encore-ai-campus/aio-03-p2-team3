## 실제 Decisions 합성 시험

기존 로컬 키·공식 OpenAI SDK의 Decisions `gpt-6-luna`, 가상 회사 맥락, 단일 exclude/keep 질문. 실제 고객 메일은 사용하지 않았다. 초기 제외 기준은 exclude 선택과 confidence ≥ 0.95이며, 확신이 낮으면 기존 그래프로 전달한다.

## 실제 Gmail 확인

- 기존 연결 토큰의 갱신/프로필 조회 성공. Gmail API 사용 권한이 현재 로컬 연결에서 동작한다.
- 사용자 제공 테스트 주소로 테스트 메일 1통을 발송했다. 이 주소는 현재 연결된 동일 Gmail 계정임을 확인했다. Gmail API가 메시지/스레드 ID를 반환했다. 자동 재발송하지 않았다.
- 다른 계정에서 보낸 가상 업무 메일 1건을 실제 수신했다. 앱에 원문이 저장되고 Decisions가 keep/confidence=1.0으로 통과시킨 뒤 기존 그래프가 실행됐다. `load_memory → analyze_email → extract_deal → check_required → make_quote → draft_replies → save_pending`의 실제 RunEvent와 awaiting_approval·후보 3개를 확인했다. 수신 그래프의 실행은 1회였다.
- 원문에 단가가 없어 국내 견적이 needs_price, 후보 3개가 pending으로 멈췄다. 사용자가 테스트 값과 선택을 위임한 뒤 검토용으로 제안한 가상 단가 10,000원·첫 후보를 선택했다. 기존 fill_prices/저장 서비스로 ready를 확정하고 기존 승인 서비스로 발송했다. 무역 조건이 있는 입력을 기존 문서 인식 정책이 국내 견적으로 선택한 점은 별도 제한이며 수출 문서의 업무 정확도가 검증된 것은 아니다.
- 가상 단가를 적용한 검토용 PDF를 DB 갱신 없이 별도 로컬 임시 파일로 생성해 1페이지·공급가액/부가세/합계 출력을 확인했다. 실제 발신자·원문·개인정보/PDF는 레포 시험 산출물에 복사하지 않는다. 실제 전송된 PDF에서도 공급가액 5,000,000원·부가세 500,000원·합계 5,500,000원을 확인했다.
- Gmail 실제 발송 성공 후 보낸편지함에서 SENT·동일 threadId·원발신자 수신 대상·원본 Message-ID와 In-Reply-To/References 일치를 확인했다. PDF 첨부는 1개였고 실제 bytes가 PDF이며 금액도 일치했다. 별도 Gmail 연결 도구에서도 SENT와 같은 스레드를 확인했다. 상대 메일 서버의 최종 수신 확인까지 주장하지 않는다.
- 성공이 확인된 같은 후보를 승인 서비스에 다시 전달하자 already_sent가 반환됐다. 해당 Gmail 스레드의 SENT 메시지는 전후 모두 1개였다. 서버의 승인 성공 기록 1개·선택 후보 sent·다른 후보 superseded·처리 메일 sent·수신 Run 1회를 확인했다. 발송 여부 불명 상황에서 재시도한 것이 아니다.
- 실제 Gmail 확인은 앱의 동일 서비스 함수와 실제 Google API로 수행했다. HTTP/React 인증·소유권·로그아웃 이후 수집·화면 조작은 실제 앱/임시 DB와 가짜 외부 공급자의 자동 검사 결과이며, 실제 익명 읽기/발송 API의 401도 확인했다. 이 두 검증 범위를 구분한다.
- 로컬 백엔드를 새 코드로 재시작했고 기존 토큰/커서를 유지했다. 앱 로그인과 수집기는 독립이다. 실제 Supabase 로그아웃 세션 소멸·운영 Render/PubSub·무역 첨부 메일 완주는 모의 검사와 별개로 남는다.

## 실제 수집의 메시지 404 재현·수정 (2026-11-18)

연결 사용자와 실제 Gmail 프로필이 일치하고 `history.list`는 성공했지만, 해당 기록의 첫 메시지 `messages.get`이 404여서 local_poll 오류와 같은 커서 재시도를 반복했다. 메시지/첨부 원문·실제 ID는 기록하지 않았다.

`tests/test_gmail_push.py::test_missing_message_does_not_block_later_mail_or_cursor`로 404 메시지 뒤 정상 메일이 처리되지 않고 커서가 1000에 남는 것을 재현했다(수정 전 실패). Google 어댑터가 메시지 조회 404만 `MessageNotFound`로 구분하고 공용 수집기는 해당 메시지만 건너뛰게 했다. history 404는 기존 만료 처리, 다른 조회/통신 실패는 기존 커서 보존을 유지한다. 삭제할 수 있는 실제 메일을 수정/복원하거나 전체 메일함 재동기화하지 않았다. 실제 로컬 수집기 적용 뒤 status=active·기존보다 진행한 커서·오류 해제를 확인했다.

## 무료 운영 범위 확인

2026-11-16 공식 문서 확인: [Gmail 쿼터](https://developers.google.com/workspace/gmail/api/reference/quota)는 표준 사용 추가 요금 없음과 일일 무료 임계값/향후 초과 과금 계획을 안내한다. 현재 표시값은 프로젝트 분당 1,200,000·사용자 분당 6,000·프로젝트 일일 80,000,000 quota units이며 프로젝트 생성 시점에 따라 기존 쿼터가 다를 수 있다. 실제 콘솔의 적용 한도를 확인해야 한다.

[Pub/Sub 요금](https://cloud.google.com/pubsub/pricing)은 결제 계정의 기본 전달량 월 첫 10GiB가 무료이며 초과·별도 저장/네트워크 비용은 구분한다. local history 조회에는 Pub/Sub를 추가하지 않았다. [Render 무료 서비스](https://render.com/docs/free)는 15분 무수신 절전이 있어 lifespan만으로 24시간 갱신을 보장하지 않는다. 유료 리소스·새 큐/크론·자동 결제 변경은 하지 않았다. DB/파일 저장 용량과 실제 계정의 월간 무료 사용량은 운영 담당 확인 대상이다.
