## 5. (사람) Google Cloud 설정 (Gmail API·OAuth·Pub/Sub) (완료)
- 할 일: Google Cloud 콘솔에서 아래를 차례로 한다. '공식 문서 확인' 표시가 있는 단계는 그 단계 전에 공식 문서로 확인하고, 결과(링크·확인 날짜)를 `.work/design/api-choice.md`에 적는다. 비밀값은 레포에 넣지 않는다. 관련 요구사항: R-04·R-14. [Request · Claude proposal]
  1. 결제(공식 문서 확인, 미확인 항목): Pub/Sub를 쓰려면 결제 계정 연결이 필요한지, 결제를 Gemini 키가 있는 프로젝트에 붙이면 Gemini 무료 등급에 영향이 있는지 확인한다. 결제 연결이 필요하면 여기서 멈추고 요청자가 정한다.
  2. Gmail API와 Cloud Pub/Sub API를 켠다.
  3. OAuth 동의 화면: 게시 상태는 프로덕션(검증 없음)(기존 결정). 확인한 사실: 테스트 상태면 테스트 사용자의 승인(갱신 토큰 포함)이 7일 뒤 만료되고, 검증 안 된 앱이 민감·제한 범위를 쓰면 경고 화면이 뜨고 새 사용자 100명 한도가 있다. 공식 문서 확인(미확인 항목): 프로덕션(검증 없음)에서 Gmail 범위 토큰이 7일 뒤 만료되는지.
  4. 범위: `docs/CONTRACT.md`의 범위 목록을 넣는다. 공식 문서 확인(제3자 문서로만 확인한 항목): `gmail.readonly`·`gmail.modify`는 제한, `gmail.send`는 민감 범위인지. 계약의 범위로 감시 등록·기록 조회·메일 읽기·발송이 되는지도 확인한다.
  5. OAuth 클라이언트(웹 애플리케이션): 리디렉션 URI에 로컬 주소와 Render 주소(4)를 넣는다.
  6. Pub/Sub 토픽을 만들고 `gmail-api-push@system.gserviceaccount.com`에 게시자(Publisher) 권한을 준다. 공식 문서 확인(제3자 문서로만 확인한 항목).
  7. 푸시 구독: 엔드포인트는 Render 주소의 알림 수신 경로, 확인 방식은 계약대로. 공식 문서 확인(미확인 항목): 잠든 Render 서버가 깨는 동안 푸시 요청이 어떻게 처리되는지(기다리는지, 실패 뒤 재전송하는지, 재전송 간격·기한).
