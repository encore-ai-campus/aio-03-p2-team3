## 1. 독립 토큰·비용 측정기 준비 (완료)

- 할 일: `app/evaluation/model_benchmark.py`의 dry run, 사전 입력 토큰 계수, 사용량/추론 토큰/비용/지연/미완료 이유, 예산 예약, 실패 비용 미상 중단을 구현한다.
- 완료 기준: 실제 키/네트워크 없이 가격 계산·캐시/추론 중복 계산 방지·사용량 미상·예산 중단·ID 환각 거부·원본 대조 필요 상태를 검증한다. `--live`를 지정하지 않으면 클라이언트를 만들지 않는다.
- 영향받는 상태·도구·노드: 독립 평가 CLI와 테스트만. 운영 `LLMResult`/그래프/DB/PC 프로토콜 변경 없음.
- 섞지 않을 것: 운영 모델 변경, 실제 API 호출, 자동 배포, 기존 PR 갱신.
- 선행 작업: 없음.
- 하는 사람: Codex.

### 측정 단위와 보고서

이 CLI는 **기능 단독 호출**을 비교한다. 실제 앱의 PI 추출 프롬프트/wire 스키마와 원문 근거 검사, 이미지 전사 지시/스키마를 재사용하지만 SDK를 직접 사용한다. LangChain 처리·Gmail 전체 StateGraph·사용자 설정 조회·승인·발송을 실행하는 시험은 아니다. SDK/프로그램의 자동 재시도도 하지 않는다. 따라서 결과 한 건을 앱의 전체 업무 1회 비용이라고 표시하지 않는다.

각 호출에 다음을 남긴다.

- case ID, 요청/응답 모델, 노력치, 요청 timeout/최대 출력, 반복 번호, provider response ID/상태/미완료 이유, 총 소요 ms.
- API `usage`의 입력·캐시 입력·출력·추론 토큰. 추론 토큰은 출력의 일부이며 따로 비용에 더하지 않는다. 누락한 내역은 unknown/null로 남긴다.
- 공식 표준 요금표 기준 추정 USD와 사전 예약액. 이는 API 청구서가 아니며 실제 과금/크레딧 적용은 공급자 대시보드와 대조한다.
- 합성 거래는 필드별 정답/정확한 원문 인용, 카탈로그는 허용 ID·복수 후보·미등록 질의의 빈 목록을 검사한다.
- 이미지 전사는 모델의 `complete=true`를 정확도로 인정하지 않는다. 별도 원본 대조 전 `passed=null`, `manual_review_required=true`다.

키/원문/예외 본문은 기본 보고서에 저장하지 않는다. 실제 이미지 원문 대조가 필요한 경우에만 `--include-output`으로 로컬 응답을 저장한다. 기존 `--out` 결과를 덮어쓰지 않아 기준 모델 결과를 보존한다.

### 비용 억제의 범위

각 생성 직전에 `responses.input_tokens.count`로 **전체 스키마·카탈로그·이미지를 포함한 입력**을 계수한다. 입력 상한 기본 60,000, 출력 상한 기본 8,192이며 `입력 전체 일반 요금 + 출력 상한 요금`을 예약해 남은 `--budget-usd`보다 크면 생성하지 않는다. 계수 실패 시 추정 문자 수로 호출하지 않는다. SDK `max_retries=0`, Standard(`service_tier=default`), `store=false`다.

시간 초과/연결 오류나 usage 누락은 실제 과금 미상이므로 예약액을 유지하고 비교 배치를 중단한다. 미완료·파싱 실패에도 반환된 usage의 비용을 집계한다. 이것은 호출 사이의 비용 억제 장치이며 공급자 차원의 결제 한도 보장은 아니다. 단가 변경·사전 계수 차이·추가 도구/저장소 사용은 별도 확인 대상이다. 이번 CLI에는 유료 내장 도구/캐시 쓰기 옵션/임베딩 호출이 없다.

## 2. 개인 PC에서 실제 모델·노력치 비교

- 할 일: 합성 정답과 사용자가 반복 실패를 본 거래 원문/이미지를 구분해 동일 조건으로 비교한다. 실제 자료는 본인 PC에서만 준비하며 이 Codex 환경에 API 키를 넣지 않는다.
- 완료 기준: 아래 실행 결과, 사용량/지연/품질 표와 API 대시보드 대조. 의미 오류와 `incomplete`, timeout, schema 거부를 서로 구분한다. 대표 실패 자료를 포함한 최소 10건씩을 정답 대조하고 조건당 3회 반복한다.
- 영향받는 상태·도구·노드: 사람의 로컬 보고서만. API 크레딧/실제 사용량 발생.
- 섞지 않을 것: 실제 메일 발송/문서 승인, 운영 모델 기본값 변경, 모델 간 무제한 자동 재시도.
- 선행 작업: 1절. PR 병합을 기다리지 않고 현재 작업 사본으로 실행 가능.
- 하는 사람: 사람.

### 현재 기준값과 비교 조건

| 경로 | 현재 기준 | 비교 후보(운영 반영 전) |
|---|---|---|
| 일반 서버 구조화 호출 | Luna, 노력치 미지정(공식 기본 medium), 요청 20초, 명시적 출력 상한 없음 | Luna/Sol × low/medium/high, 90초/8,192부터 비교 |
| PC 구조화 호출 | Luna, 노력치 미지정(기본 medium), 요청 20초, 기본 출력 2,048, 큐 전체 120초 | 20초/2,048 기준과 90초/8,192 비교, 큐/임대/HTTP 기한은 이후 함께 변경 |
| 지식 문서 이미지 전사 | 현재 비전 모델(별도 미지정이면 Luna), 기본 medium, 180초, 출력 10,000, SDK 재시도 최대 3회 | Luna/Terra × low/medium/high, 단독 측정의 SDK 재시도 0으로 먼저 비교 |

노력치는 토큰 수를 고정하지 않는다. 같은 medium도 입력과 모델에 따라 추론량이 달라진다. 출력 상한에는 내부 추론도 포함되므로 2,048에서 생각에 토큰을 써 버리면 최종 JSON이 잘릴 수 있다. high는 무조건 좋은 설정이 아니며 개선 폭과 지연/비용을 비교한다. 이번 도구는 none도 지원하지만 Sol의 none은 실행 전 거부한다.

### 실행 순서

레포 루트의 Python 3.12/`uv sync` 환경에서 실행한다. 키는 **본인 PC의 환경변수**에만 설정한다. 이 CLI는 `.env`를 자동으로 읽거나 앱 DB의 키를 꺼내지 않는다. PowerShell도 명령을 한 줄로 입력할 수 있다. 아래 파일명은 모두 서로 달라 기존 결과를 덮어쓰지 않는다.

1. 무료 준비 확인(API 미호출):

   ```sh
   uv run python -m app.evaluation.model_benchmark --out work/llm-benchmark/dry.json
   ```

2. 기존 PC 한도 재현: 단독 복합 거래 1건, 최대 예산 $0.10. 이 단계가 실패해도 응답/사용량/미완료 이유를 먼저 확인한다.

   ```sh
   uv run python -m app.evaluation.model_benchmark --live --models gpt-6-luna --efforts medium --cases trade --timeout 20 --max-output-tokens 2048 --budget-usd 0.10 --out work/llm-benchmark/luna-legacy.json
   ```

3. 카탈로그 혼용 3질의 + 복합 거래 1건을 모델/노력치별로 비교한다. 먼저 repeat=1로 총 36회 이하를 $1 예산 안에서 실행하고, 통과한 후보만 반복한다. 출력 상한 예약 때문에 예산에 도달하면 일부 조건이 실행되지 않을 수 있다. `budget_stopped`는 모델 정확도 실패가 아니다.

   ```sh
   uv run python -m app.evaluation.model_benchmark --live --models gpt-6-luna gpt-6.1-sol gpt-6.1-terra --efforts low medium high --cases trade catalog --timeout 90 --max-output-tokens 8192 --budget-usd 1 --out work/llm-benchmark/text-comparison.json
   ```

4. 본인 PC에서 실패한 원본 페이지를 PNG/JPEG로 준비한다(8MiB 이하). 같은 해상도·크롭으로 비교하고 `--include-output`으로 응답을 로컬 원본과 대조한다. 실제 전사 오류 자료가 없다면 작은 글씨/병합 셀/0·O/숫자·각주/빈칸이 있는 합성 페이지부터 시험한다. XLSX/문서 전체를 이 명령에 직접 넣지 않는다.

   ```sh
   uv run python -m app.evaluation.model_benchmark --live --models gpt-6-luna gpt-6.1-terra --efforts low medium high --cases vision --image work/llm-benchmark/page.png --timeout 180 --max-output-tokens 10000 --budget-usd 1 --include-output --out work/llm-benchmark/vision-comparison.json
   ```

5. 반복은 통과 후보만 `--repeats 3`으로 수행한다. 실제 반복 오류의 해결을 기본 합성 4건만으로 확정하지 않는다. 실제 거래는 `--trade-input work/failing.txt --trade-expected work/expected.json`을 함께 추가한다. 정답은 `{"header":{"currency":"USD"},"items":[{"product_name":"정확한 제품명","paid_quantity":"10","free_quantity":"2","discount_percent":"5","unit_price":"140"}]}` 형식이다. 지정한 header/품목 필드와 품목 수·원문 인용을 비교한다. 모든 실패 자료를 개별 파일/새 보고서로 시험한다.

   자체 카탈로그는 `--catalog-input work/catalog-test.json`으로 넣는다. 형식은 `{"products":[{"id":"cream","item_name":"Hydrating Gel Cream"}],"queries":[{"id":"cream-ko","query":"하이드레이팅 젤크림","expected_ids":["cream"]}]}`다. 1~200개 ID/이름·선택 규격/코드만 전송하고 가격은 제거한다. 해당 카탈로그에 없는 ID/중복 ID는 거부한다. 데이터별 정답은 시험 전에 사람이 확인한다.

### 실제 업무 1회 비용으로 확장하는 기록 계약

메일 하나/문서 하나/업로드 하나를 `work_unit_id`로 묶고, 하위 `call_id`/시도/단계(분류·추출·답장·요약·성찰·검색·페이지 전사·임베딩)를 기록한다. 각 단계의 usage를 모으되 reasoning은 output의 부분집합, cached는 input의 부분집합으로 취급한다. 이미지 페이지 수·임베딩·재처리·실패한 시도를 포함한다. 실패 usage가 하나라도 미상이면 합계는 **알려진 비용 + 미상**으로 표시한다. SDK 내부 재시도까지 계측하기 전에는 완전한 1회 비용이라고 표시하지 않는다.

최소 보고 항목: 입력/캐시/출력/추론 합계, 호출·재시도 수, 총/단계별 ms, 정확도/필드 오류, 평균·최댓값(충분한 표본에서 p95), Standard 요금 추계, 실제 크레딧 차감 대조. 같은 자료/모델/노력치를 쓰고 한 번에 한 요인만 변경한다.

### 비용 예시 — 실제 측정값 아님

2026-11-17 Standard, 100만 토큰당 입력/출력: Luna $0.10/$0.50, Terra $1/$5, Sol $2/$10. 아래 출력은 **추론 포함 총출력**이며 캐시·임베딩·재시도·도구 비용을 제외한 가정이다.

| 작업 가정 | 입력/출력 토큰 | Luna | Terra | Sol |
|---|---:|---:|---:|---:|
| 복합 거래 추출 1회 | 8,000 / 3,000 | $0.0023 | $0.023 | $0.046 |
| 이미지 전사 1페이지 | 12,000 / 6,000 | $0.0042 | $0.042 | $0.084 |
| 추출 1회 + 전사 3페이지 | 44,000 / 21,000 | $0.0149 | $0.149 | $0.298 |

텍스트 Sol 1회 + 이미지 Terra 3페이지라면 같은 가정으로 $0.172다. 실제 사진은 해상도·detail·페이지 수에 따라 입력 토큰이 달라진다. 노력치에 고정 가격 배수를 적용하지 않고 실제 usage를 쓴다. 한 업무가 LLM을 호출하지 않는 직접 입력/검색/계산만 수행하면 LLM 토큰은 0이다.

## 3. 사전 없는 카탈로그 후보 해석

- 할 일: 사용자 소유 카탈로그의 ID/이름/규격만 LLM에 주고 한·영 혼용 입력에 해당하는 ID 목록을 받는다. 15개 시연 카탈로그는 전체를 전달할 수 있으므로 별칭 사전/벡터 DB가 선행 조건은 아니다. 질의/카탈로그는 명령이 아닌 데이터로 처리한다.
- 완료 기준: 서로 다른 브랜드/종류의 미등록 한글 발음·혼용·오타·색상/세대 모호성·품목 없음·명령 삽입을 시험한다. 서버가 현재 사용자·카탈로그 버전·허용 ID를 다시 확인하고 존재하지 않는 ID는 거부한다. 색상/Compact/세대를 임의 확정하지 않고 최종 선택은 사용자에게 받는다.
- 영향받는 상태·도구·노드: 기존 후보 검색 API/UI와 새 AI 후보 해석 어댑터. 키/실행 모드/PC 지원 경계를 기존 계약과 맞춘다. 저장·단가·승인에는 권한을 주지 않는다.
- 섞지 않을 것: 카탈로그 밖 제품/단가 생성, 가격 자동 승인, 모든 대형 카탈로그를 무조건 통째로 전달하는 구현.
- 선행 작업: 2절의 품질·비용 결과와 모델 선택. 이후 프로그램 수정 PR에 포함한다.
- 하는 사람: Codex.

문자열 검색만으로 후보를 먼저 좁혀 버리면 `울트라샤프`→`UltraSharp` 같은 경우 처음부터 정답이 탈락한다. 대규모 카탈로그는 다국어 의미 검색/분할 검색의 후보 재현율을 별도로 검증한다. LLM이 한 번 ID를 제안했다는 사실은 제품 일치의 확정 근거가 아니다. 기존 250ms 입력 검색마다 LLM을 호출하지 않고 명시적 “AI 후보 찾기” 동작과 질의/사용자/카탈로그 버전별 캐시·호출 한도를 설계한다.

키/예산/시간/모델 오류이면 수량과 원문을 보존해 기존 후보/직접 선택으로 복귀한다. 이 기능을 MVP에 넣지 못하거나 품질 기준을 통과하지 못하면 화면·발표에 **“현재 자동 품목 검색은 영어 제품명 부분검색·오타검색 기준입니다. 다국어 자동 연결은 지원하지 않습니다.”**를 명시한다. 다국어 AI가 일시 실패하면 영어 재검색/직접 선택을 안내한다. 일부 한글 별칭이 동작한다는 이유로 일반 다국어 지원이라고 표현하지 않는다.

## 4. 모델·노력치·기한·출력 상한과 복귀 기능

- 할 일: 측정으로 통과한 텍스트/비전 프로필을 모델·노력치·timeout·출력 상한의 묶음으로 설정 가능하게 하고 서버/PC 요청·큐/임대/heartbeat·HTTP/프런트 요청 기한을 함께 맞춘다. 변경 전 Luna/default medium/기존 기한·출력 정책을 비밀값 없는 명명된 baseline 프로필로 보존한다.
- 완료 기준: 기존 모델로 설정 전환·재시작 후 동일 실패 자료를 재시험할 수 있다. 신규 모델/프로필은 새 시도에만 적용하고 발급 파일·기존 처리 프로필을 바꾸지 않는다. 시간 초과·JSON 미완료·원문/이미지 근거 오류·모델 권한/잔액 오류를 서로 구분한다. PC 모델/스키마 일치 검사를 우회하지 않는다.
- 영향받는 상태·도구·노드: `app/llm/client.py`, `config.py`, `worker/adapter.py`·`pc.py`·프로토콜/서비스 기한, `knowledge/extract.py`, 프런트 요청 기한과 관련 계약/README/환경 예시. 공통 경계 변경은 기존 담당자와 조율한다.
- 섞지 않을 것: 성능 측정 없이 제한을 무조건 크게 늘리기, 메일/문서 외부 효과 자동 재실행, 다른 사람/공용 키 대체.
- 선행 작업: 2절의 실측·모델 선택. 3절의 후보 해석은 별도 기능으로 연결한다.
- 하는 사람: Codex.

기본 복귀는 **명시적인 기존 프로필 선택**이다. 프로그램에 자동 fallback을 추가한다면 실패 종류별로 허용하고 한도/비용을 따로 측정한다. timeout은 앞 요청이 공급자에서 처리됐을 수 있어 자동 재요청하지 않고 입력 보존/사용자 재시도를 우선한다. 알려진 형식 실패에서 기존 모델을 한 번 더 호출하더라도 새 후보/새 검토로 취급하고 두 모델 비용을 합친다. 가격·문서 승인·메일 발송을 재생하지 않는다. 비전 모델 변경 시 기존 문서는 명시적 재처리만 수행한다.

기존 모델 결과와 모델별 품질 표를 삭제하지 않고 보존한다. rollback 이유/시각/프로필 ID를 남기되 API 키를 파일·로그·Git에 복사하지 않는다. `OPENAI_MODEL` 변경만으로 노력치·기한·PC 출력 제한까지 함께 바뀌는 것처럼 안내하지 않는다.
