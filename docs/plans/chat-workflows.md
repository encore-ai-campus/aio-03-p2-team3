# 업무 채팅 도구와 화면 확장 계획

- 목표: 일정 조회에 이어 메일·거래처·단가·무역서류의 남은 업무를 채팅에서 처리하고, Markdown 답변과 기능별 결과·입력·승인 화면을 제공한다.
- 관련 Issue: 계획 병합 시 각 절의 실행 Issue를 별도로 관리한다.
- 관련 요구사항: R-02·R-03·R-07·R-08·R-09·R-11·R-12·R-14.
- 조율함: 미확인. 공통 그래프·도구를 바꾸는 각 절에서 해당 파일 변경을 PR에 명시한다.

첫 절에서 채팅 메시지와 도구 카드의 표시 규약을 정한다. 뒤 절은 인증된 사용자를 서버에서 주입하고 기존 LangGraph 노드·포트·결과 타임라인을 사용한다. 결과는 기존 결과 data에 업무별 구조화 필드를 담는다. 내용은 React 노드로 렌더링하며 실패·빈 결과·입력 대기·승인·성공은 실행 상태에서 가져온다. 쓰기 성공을 모델 답변으로 판정하지 않는다. 실제 사용자 업무 대신 합성 자료로 정상과 경계를 시험한다.

## 1. Markdown 답변과 결과 카드 (완료)
- 할 일: Taste 디자인 스킬로 업무 채팅 답변을 정리한다. 답변 본문의 제목·강조·링크·목록·표·인용·코드와 기능별 결과 카드의 표시 규약을 정한다. 기존 색·글꼴·승인 동작을 재사용하고 가로 스크롤은 긴 표와 코드 영역 내부에 둔다.
- 완료 기준: 실제 대화 페이지에서 Markdown 기호가 그대로 붙어 보이지 않고, 표·목록·코드·안전한 링크가 의미에 맞게 렌더링된다. 작은 화면에서 넘침과 키보드 조작을 확인한다. 원시 HTML, 위험한 링크, 일반 텍스트 코드 예제를 검증한다.
- 영향받는 상태·도구·노드: 답변 투영과 React AgentPage·공용 표시 규약.
- 섞지 않을 것: 새 외부 서비스와 업무 도구.
- 선행 작업: 없음.
- 하는 사람: Codex.

후속 결과 카드 규약: 각 업무의 타임라인 상세에 짧은 상태 문구와 구조화된 결과를 놓는다. 여러 결과는 제목부터 읽히는 목록이나 표로, 단건은 항목명과 값을 짝지어 보여준다. 이어서 할 일은 같은 카드에 링크 또는 버튼으로 둔다. 선택·편집·승인은 대기 카드에 두고 실제 상태와 완료 메시지는 서버 투영을 사용한다. 색만으로 상태를 표시하지 않고 390px에서도 상세와 버튼을 사용할 수 있게 검증한다.

## 2. 메일 본문·기간·미답장 검색 (완료)
- 할 일: 기존 메일 검색에 제목·본문·발신자, 수신 시각과 실제 답장 발송 여부 조건을 추가한다. 채팅 결과는 검색 범위, 스레드 링크, 발신자, 받은 시각과 본문 일치 미리보기를 표시한다.
- 완료 기준: 본문에만 있는 검색어, 날짜 경계, 발송 전 초안, 같은 스레드의 후속 수신, 기존 발송 여부와 다음 페이지를 확인한다. 다른 계정은 제외한다.
- 영향받는 상태·도구·노드: search_mail, MailStore, 메일 노드·검색 결과 카드.
- 섞지 않을 것: Gmail 전체 과거 메일의 자동 동기화, 메일 발송.
- 선행 작업: 1절.
- 하는 사람: Codex.

## 3. 등록 단가표와 거래처 카드 조회 (완료)
- 할 일: 본인 단가표와 등록 거래처를 직접 읽는 도구를 기존 무역 설정·품목 검색에 연결한다. 채팅에 품목 코드·통화·단가 기준·거래처 또는 연락처를 보여준다.
- 완료 기준: 등록 SKU와 거래처 별칭, 거래처별 단가와 공통 단가 구분, 정확한 통화, 동명이인 후보, 미등록·다른 계정 유출 방지를 검증한다.
- 영향받는 상태·도구·노드: 무역 설정 데이터, 문서 업무 읽기 노드, 단가표·거래처 카드.
- 섞지 않을 것: 단가 변경, 계약서 근거를 등록 단가로 사용.
- 선행 작업: 1·2절.
- 하는 사람: Codex.

## 4. 등록 일정 변경과 취소
- 할 일: 기존 기본 캘린더 일정 조회로 대상을 찾아 변경·취소를 제안한다. 화면에서 일정 제목, 이전·이후 시간, 취소 범위와 승인 여부를 보여준다. 중복 이름은 후보 선택을 받는다.
- 완료 기준: 승인 전 쓰기 없음, 이동 충돌과 최신 일정 재검사, 취소, 이미 변경된 대상, 반복 일정의 회차, 승인 재생과 타임아웃 상태 확인을 시험한다.
- 영향받는 상태·도구·노드: CalendarPort, 일정 노드, action·영수증, 일정 선택과 승인 카드.
- 섞지 않을 것: 사용자 승인 없는 Google 쓰기, 대상이 정해지지 않은 반복 일정 전체 변경.
- 선행 작업: 1·3절.
- 하는 사람: Codex.

## 5. 새 메일 초안
- 할 일: 받는 사람·제목·본문을 작성하고 채팅의 편집 가능한 초안 카드에서 검토한다. 확인된 초안을 본인 업무 초안으로 저장하고 다시 열 수 있게 한다.
- 완료 기준: 스레드가 없는 새 초안 보존·새로고침, 잘못된 주소, 타인 접근 차단과 작업 중복에도 메일이 발송되지 않는지 검증한다.
- 영향받는 상태·도구·노드: 메일 초안 저장소·메일 노드·새 메일 편집 카드.
- 섞지 않을 것: 발송, 캠페인 및 자동 회신.
- 선행 작업: 1·4절.
- 하는 사람: Codex.

## 6. 기존 답장 초안 편집
- 할 일: 메일 검색에서 저장된 답장 후보를 확인한 뒤 실제 초안 편집 기능을 채팅 도구와 카드에 연결한다. 사용자가 수정 문안과 대상 후보를 확인할 수 있게 한다.
- 완료 기준: 첫 문장만 바꾸라는 요청을 처리하고 나머지 문장 보존·새로고침·오래된 스냅샷·발송된 초안·복수 후보 선택을 확인한다.
- 영향받는 상태·도구·노드: 기존 답장 편집 서비스, 메일 노드, 초안 선택/편집 카드.
- 섞지 않을 것: 후보의 자동 선택과 발송.
- 선행 작업: 1·5절.
- 하는 사람: Codex.

## 7. 미완성 무역서류 목록
- 할 일: 작성 중인 본인 PI·PO·CI·PL을 문서 목록에서 찾아 최신 누락 항목, 상태와 이어 쓰기 링크를 제공한다. 채팅 카드에서 종류·번호·거래처·누락 조건을 표시한다.
- 완료 기준: 발급본 제외, 종류 필터, 최신 revision, 누락 항목, 빈 결과와 다른 계정 제외를 확인한다.
- 영향받는 상태·도구·노드: 기존 문서 목록과 입력 검증, 문서 노드, 미완성 문서 카드.
- 섞지 않을 것: 초안 자동 수정이나 문서 발급.
- 선행 작업: 1·6절.
- 하는 사람: Codex.

## 8. 메일 첨부 원본 보기
- 할 일: 본인에게 수집된 메일의 정확한 메시지에서 첨부 메타데이터를 확인하고 인증된 원본 조회를 연결한다. 채팅에서 파일명·종류·크기, 미리보기나 내려받기를 표시한다.
- 완료 기준: 본문에 언급만 된 파일, 실제 첨부, 복수 첨부, 잘못된 스레드·파일 ID, 계정 경계, Gmail 미연결과 읽기 실패를 확인한다.
- 영향받는 상태·도구·노드: Gmail 읽기와 메일 원문 조회, 첨부 결과 카드.
- 섞지 않을 것: 첨부를 자동 실행하거나 문서함에 자동 업로드.
- 선행 작업: 1·7절.
- 하는 사람: Codex.

## 9. 답장이 없을 때 후속 알림
- 할 일: 상대 답장 여부를 조건으로 하는 확인 알림을 등록·조회·취소한다. 채팅 카드에서 메일, 기준 시각, 기한, 상태를 표시한다. 서비스에서 주기적으로 조건을 확인해 앱 안에서 알린다.
- 완료 기준: “사흘 동안 답 없으면 알려줘”를 등록하고, 기한 전 도착·기한까지 미도착·중복 실행·재시작·취소·다른 계정 차단을 시험한다.
- 영향받는 상태·도구·노드: 메일 알림 조건과 실행 상태, 기존 메일 수집/작업 현황, 등록·취소 카드.
- 섞지 않을 것: 자동 회신과 캘린더에 대신 등록.
- 선행 작업: 1·8절.
- 하는 사람: Codex.
