# 무역 문서 최신 설정 적용·누락 정보 팝업 계획

- 목표: PI·PO·CI·PL에서 최신 설정을 새 문서 버전에 일관되게 반영하고, 승인·파일 발급 전에 필요한 누락 정보를 기존 업무별 입력 규칙에 맞는 팝업에서 보완한다.
- 관련 요구사항: R-03(누락 보완), R-11(오류·재시도 안내), R-14(사용자 화면).
- 관련 Issue: 없음.
- 조율함: 해당 없음 — 그래프 상태·도구 스키마·노드·엣지를 변경하지 않는다.
- 진행 방식: 요청자의 후속 지시에 따라 1·2절을 한 작업에서 구현한다. 사전 런타임·회귀·빌드 검사는 실행하지 않으며, 사용자의 별도 요청 후 수행한다.

## 현재 코드 확인

- 구현 전 확인: 최신 설정 적용은 PI 전용 `/refresh-issuer`였다. 누락 정보 입력도 문서별 입력 단계로 이동하는 방식이었다.
- 구현에서 재사용: 기존 설정 저장소·문서 계산/검증·revision 생성·승인/파일 고정 경로를 유지한다. 회사 이미지는 새 검토 제안을 만들 때 최신 설정에서 읽으며, 이미 승인된 파일은 변경하지 않는다.
- CI 연결형 기준은 요청자 답변으로 확정했다: 같은 PI 문서의 최신 승인 버전을 적용하고 해당 버전의 거래처·품목·수량·가격을 사용한다. CI 문서번호·선적 입력은 유지한다. 설정 거래처는 저장 이름과 일치하는 경우만 반영한다.

## 1. 네 문서 최신 설정 적용 (구현 완료·검증 대기)
- 할 일: PI의 기존 새 revision/발급 파일 보존 규칙을 바탕으로 공통 최신 설정 적용 API와 PI·PO·CI·PL 버튼을 연결한다. 회사·거래처·계좌·단가표의 최신값을 문서가 사용하는 필드에 적용한다. 이미지 설정은 새 검토 제안에서 최신값을 읽는다. 명시적으로 수기 입력하거나 확정한 거래 단가는 보존한다. CI 연결형은 같은 원본 PI의 최신 승인 revision에서 거래처·품목·수량·가격을 가져오고 일치하는 거래처 프로필을 적용하며 CI 문서번호·선적 입력은 유지한다. 최신 설정을 적용한 문서는 새 revision에서 다시 검토·승인하며 과거 발급 파일은 보존한다.
- 완료 기준: PI·PO·CI(연결/단독)·PL 각각의 검토 화면에 같은 위치·상태 규칙으로 버튼을 연결했다. 새 revision은 최신 설정을 사용하며 수기/확정 단가, PI 연결형 최신 승인 source revision, CI 선적 정보, PL 포장 재승인 규칙, 이전 발급 파일 보존 계약을 유지한다. 검증은 요청자의 별도 지시 후 수행한다.
- 영향받는 상태·도구·노드: 문서 입력·revision·검토 proposal·CI source PI revision, 문서 HTTP API 및 UI callback. 그래프 상태·도구·노드 변경 없음.
- 섞지 않을 것: 새 가격 산정/승인 규칙, 수기·명시적 확정 단가 변경, 과거 승인 파일 덮어쓰기, 다른 PI 문서로의 자동 변경, 메일 발송, 그래프 변경.
- 선행 작업: 없음.
- 하는 사람: Codex.

## 2. 누락 정보 입력 팝업 (구현 완료·검증 대기)
- 할 일: 공통 접근성 팝업을 만들고 PI·PO·CI 연결/단독·PL의 최종 검토 오류 영역에서 필요한 입력만 팝업으로 연다. 기존 문서 입력 필드와 저장/재검토 API를 재사용한다. PL 포장 행 오류는 해당 수량·단위·포장 수·중량·부피 필드를 팝업에 표시한다. CI 연결형에서 원본 PI 자체를 보완해야 하는 오류는 CI에서 원본 거래 사실을 직접 바꾸지 않는다.
- 완료 기준: 네 문서의 필수 누락과 PL 포장 행 오류를 위한 팝업을 연결했다. 값을 수정하면 기존 저장 흐름으로 반영한다. 실행·회귀·접근성 확인은 요청자의 별도 지시 후 수행한다.
- 영향받는 상태·도구·노드: UI draft·현재 단계·dialog 열림 상태·document revision/proposal. 그래프 상태·도구·노드 변경 없음.
- 섞지 않을 것: 문서별 필수 필드 정의 변경, 새 자동 저장/승인, AI 추출 방식 변경, CI의 고정 source PI 사실을 팝업에서 직접 수정.
- 선행 작업: 1절.
- 하는 사람: Codex.
