# local-openai-execution — 개인 PC의 .env로 AI 실행

- 목표: ① 개인 PC에서 서비스 전체를 실행해 본인 `.env` 키를 사용하는 방식과 ② 공용 Render 화면을 사용하면서 개인 PC 실행 프로그램이 OpenAI 호출을 맡는 방식을 모두 제공한다. 두 방식 모두 개인 OpenAI 키를 공용 서버로 전송하거나 공용 DB에 저장하지 않는다.
- 요청 근거: 2026-11-12, 사용자가 서비스에 키를 맡기지 않으려는 사용자를 위해 두 방식 모두 지원해 달라고 요청했다.
- 현재 기준: PR #152의 사용자별 암호화 키 등록이 main에 병합됐다. 현재 `OPENAI_API_KEY`는 로컬에서도 AI 호출에 사용되지 않는다. 이 문서는 구현 계획이며 아래 기능은 아직 구현되지 않았다.
- 관련 요구사항: R-04(외부 API), R-05(상태), R-11(오류·종료), R-12(정상·오류 검증), R-14(화면·배포).
- 관련 Issue: 1=[#153](https://github.com/encore-ai-campus/aio-03-p2-team3/issues/153), 2=[#154](https://github.com/encore-ai-campus/aio-03-p2-team3/issues/154), 3=[#155](https://github.com/encore-ai-campus/aio-03-p2-team3/issues/155), 4=[#156](https://github.com/encore-ai-campus/aio-03-p2-team3/issues/156), 5=[#157](https://github.com/encore-ai-campus/aio-03-p2-team3/issues/157)
- 조율함: 미확인. 이 계획 PR은 그래프 상태·도구·노드를 바꾸지 않는다. 구현 시 공통 기반 담당 김민성 및 해당 부분 작업자와 조율하고 공통 계약과 코드를 함께 반영한다.

## 사용 형태와 데이터 경계

| 형태 | 접속 화면 | OpenAI 호출 위치 | OpenAI 키 보관 | Gmail 처리 |
|---|---|---|---|---|
| 기존 서버 등록 | 공용 Render | Render | 사용자별 Fernet 암호문 | 기존 공용 OAuth·Pub/Sub |
| 로컬 전체 실행 | 본인 PC의 localhost | 본인 PC | 본인 .env, 키 DB 저장 없음 | 로컬 Google 연결과 새 메일 수집 필요 |
| Render + 개인 실행 프로그램 | 공용 Render | 본인 PC | 본인 .env, Render에 전송 없음 | 공용 서버가 메일 수신·승인/발송, PC가 AI 호출 |

- 공용 웹페이지가 개인 PC의 `.env`를 읽는 방식은 사용하지 않는다. 브라우저에 OpenAI 키를 전달하지 않는다.
- 서버에 키를 저장하지 않아도 메일·문서 입력과 AI 결과는 Render를 거친다. 이 지원은 OpenAI 키를 맡기지 않는 기능이며 메일 내용까지 서버에서 숨기는 기능은 아니다.
- 개인 실행 프로그램은 PC에서 허용한 서비스 주소·본인 계정의 작업만 받는다. 사용자가 시작/중지할 수 있고 모델·출력 토큰·요청 빈도·동시 실행 상한을 PC에서 제한한다. 공용 서버가 이 상한을 높일 수 없어야 한다.
- PC가 꺼져 있거나 프로그램이 중지됐을 때 AI 작업을 대기/실패로 안내하며, 기존 서버 저장 키나 서버 환경변수 키로 자동 전환하지 않는다.
- 기존 서버 등록 방식은 별도 선택지로 유지한다. 사용자가 선택한 실행 방식의 실패를 다른 키 소스로 대체하지 않는다.
- 로컬 `.env`는 사용자가 관리하는 평문 비밀 파일이다. Git·로그·오류 응답·화면·업로드·동기화 대상에 포함하지 않는다. 소스 코드와 PC 환경을 신뢰하고 실행한다는 경계는 남는다.
- 초기 구현 범위는 한 사용자당 활성 개인 실행 프로그램 한 대다. 여러 사용자 각각의 PC는 동시에 연결할 수 있어야 한다. 다중 장치 부하 분산은 포함하지 않는다.

## 1. 로컬 .env 키 모드와 공통 실행 계약 (완료)

- 할 일:
  - `AI_RUNTIME=server|local`을 명시적으로 구분하고 기본값은 `server`로 둔다. `local`에서만 `OPENAI_API_KEY`를 읽고 DB의 사용자 키를 읽거나 저장하지 않는다.
  - `LOCAL_OWNER_GOOGLE_SUB`로 지정한 본인의 검증된 Google 사용자만 로컬 키를 사용할 수 있게 한다. 최초 로그인으로 확인한 본인의 식별자를 로컬에서 확인·지정하는 절차를 제공하고, 최초 방문자를 자동으로 소유자로 지정하지 않는다.
  - 루프백에만 바인딩하는 전용 로컬 실행 명령을 제공한다. 공용 실행·Render에서 로컬 키 모드가 켜지면 시작을 거부하고, Host 헤더나 `APP_BASE_URL`만으로 로컬 실행을 판정하지 않는다.
  - 키가 없거나 지정 사용자와 다르면 차단한다. 로컬 키 등록 안내는 `.env` 사용 상태를 정확히 표시하고 키 원문·해시·일부 문자열은 노출하지 않는다.
  - 뒤 절들이 함께 사용할 계약을 `docs/CONTRACT.md` 6절에 확정한다. 서버 사용자별 실행 방식(`stored_key|local_worker`, 기본 `stored_key`), 키 소스 선택, 장치 연결 인증, 작업 요청/응답·버전·크기 제한·만료·오류·시간 제한을 정의한다.
  - 3·4절의 작업 계약은 허용된 프롬프트 ID/버전·출력 스키마 ID/버전·변수·요청 모델·작업/시도 ID를 전달하고, 검증된 결과 또는 안전한 오류 종류만 받는 구조화 AI 호출로 제한한다. 코드·셸 명령·임의 URL·임의 HTTP 헤더를 실행하는 작업은 금지한다.
  - `.env.example`·README·API 선택 문서·최신 흐름을 실제 구현 상태에 맞춘다. 이후 절의 아직 없는 실행 방식을 사용할 수 있는 것처럼 표시하지 않는다.
- 완료 기준:
  - 실제 설정 로더로 `.env`를 읽는 시험과 모의 OpenAI HTTP로, 본인 로컬 실행만 환경 키를 사용하고 공용 서버에는 어떤 사용자의 키 누락에도 환경 키가 사용되지 않음을 검증한다.
  - 다른 사용자·사용자 범위 밖·소유자 미지정·키 누락·공용 실행에서 로컬 모드 거부, 키 비노출과 DB 미저장을 확인한다.
  - 기존 사용자 DB 키 방식·가짜 백엔드 주입·메일과 네 문서 회귀가 통과한다. 공통 실행 계약을 후속 작업이 읽을 수 있다.
- 영향받는 상태·도구·노드: `app/config.py`, `app/services/openai_keys.py`, `app/llm/client.py`, 로컬 실행 진입점과 설정 안내, `docs/CONTRACT.md` 6절. 키·장치 토큰은 AgentState에 추가하지 않고 기존 노드·엣지를 유지한다.
- 섞지 않을 것: 개인 PC Gmail 수집, Render 장치 연결·작업 큐·개인 실행 프로그램, 공용 서버 키 fallback 재도입.
- 선행 작업: 없음. 이 계획 PR 병합 후 시작한다.
- 하는 사람: Codex.

## 2. 로컬 서비스의 Gmail 연결과 새 메일 수집 (완료)

- 할 일:
  - 1절에서 확정한 `docs/CONTRACT.md` 6절을 읽고 로컬 모드를 따른다. 로컬 사용자가 본인 Google OAuth 앱과 localhost 콜백을 설정하는 절차를 문서화한다. 운영용 OAuth 클라이언트 비밀값을 팀원에게 배포하지 않는다.
  - 로컬 모드에서는 본인 Google 토큰으로 Gmail history를 주기적으로 조회하는 수집 실행기를 제공한다. 공용 Pub/Sub 설정은 변경하지 않고 개인 PC에 수신 포트·공개 터널을 요구하지 않는다.
  - 로컬 로그인은 공용 `GMAIL_PUBSUB_TOPIC` 없이 가능하게 하고 로컬 상태 안내를 구분한다. 첫 연결은 현재 historyId부터 시작하며 연결 전 전체 메일함을 자동으로 처리하지 않는다.
  - 기존 MIME 변환·필터·사용자별 중복 방지·history 커서 갱신·`start_run()`·사용자 승인 후 발송을 재사용한다. 로컬 수집과 공용 watch 등록이 같은 계정의 감시를 덮어쓰지 않게 로컬에서 watch/stop 호출을 하지 않는다.
  - 로그아웃·연결 취소·토큰 만료·PC 중지 때 수집을 멈춘다. 만료된 historyId는 재연결 안내를 하고 과거 메일을 무제한 재처리하지 않는다.
- 완료 기준:
  - 가짜 Google와 실제 로컬 실행 경로로 새 메일 수집→본인 .env 키로 AI 후보 생성→사용자 승인 후 1회 발송을 확인한다.
  - 같은 메일 재조회·페이지 이어 읽기·조회 실패 후 재개·history 만료·다른 사용자 격리를 검증한다. 공용 Gmail watch/stop과 Pub/Sub 설정이 바뀌지 않는다.
  - 로컬과 공용 모드의 로그인·감시·승인 기존 회귀, 전체 테스트·규칙 검사가 통과한다.
- 영향받는 상태·도구·노드: Google 로그인·접근 토큰·로컬 수집 서비스, `app/services/gmail_push.py`의 재사용 경계, `app/services/watch.py`, 상태 안내와 계약 7·9·10절. 그래프 업무 노드·전이는 유지한다.
- 섞지 않을 것: 공용 서버에서 PC로 작업 위임, Pub/Sub 구독 주소 변경, 운영 비밀값 공유, 자동 메일 발송.
- 선행 작업: 1.
- 하는 사람: Codex.

## 3. Render의 개인 실행 프로그램 연결과 사용자별 작업 큐

- 할 일:
  - 1절의 공통 실행 계약을 읽고 서버 사용자별 실행 방식과 장치 연결·해제 API, 장치/작업 DB 표·마이그레이션을 구현한다.
  - Google 로그인과 CSRF를 확인한 사용자가 만료·단일 사용 연결 코드를 발급하고 연결 대상을 승인한다. 장치 자격증명은 OpenAI 키와 별개이며 서버에는 검증용 해시만 저장한다. 자격증명 발급·조회·교체·취소에 원문 비노출·횟수 제한을 적용한다.
  - 프로그램이 서버로 보내는 outbound HTTPS 요청으로 자기 작업을 가져오고 결과를 제출하게 한다. 서버가 개인 PC로 들어오는 연결이나 공개 PC 포트를 요구하지 않는다.
  - 대기·임대/실행 중·완료·실패·만료 상태와 작업 소유자, 장치, 시도 ID, 임대 만료를 저장한다. 작업 수신/결과 제출 권한은 본인 AI 작업에만 한정하고 Gmail 승인·발송 권한을 부여하지 않는다.
  - 조건부 claim·결과의 소유자/시도 검증·크기/스키마/버전 검증으로 중복 수신·위조·기한 지난 결과가 업무 결과에 반영되지 않게 한다. 이미 OpenAI로 전송됐을 수 있는 작업은 임대 만료만으로 자동 중복 배포하지 않는다.
  - 사용자에게 연결 상태·선택 모드·해제 동작을 제공한다. 취소/오프라인/만료 오류와 시간 제한을 계약대로 처리하고 DB 트랜잭션을 네트워크 대기 동안 유지하지 않는다.
- 완료 기준:
  - 실제 ASGI·DB 시험에서 서로 다른 두 사용자의 장치/작업/결과가 격리된다. 탈취 전제의 다른 사용자 토큰·연결 코드 재사용·CSRF 누락·동시 claim·중복 결과·취소/만료 뒤 결과가 거부된다.
  - 서버 재시작 후 작업·장치 상태가 보존되고, 중단된 작업은 명확한 오류/만료 상태로 정리된다. 외부 OpenAI 호출이나 메일 발송의 exactly-once를 보장한다고 표시하지 않는다.
  - 이 단계까지 OpenAI 키는 서버 API의 입력 필드나 장치 DB에 생기지 않는다. 4절이 완성되기 전에는 실제 AI 실행 완료로 안내하지 않는다.
- 영향받는 상태·도구·노드: 사용자별 AI 실행 설정, 장치/작업 표, 인증된 연결·작업 API와 설정 화면, 계약 6·7·9절. AgentState·기억에 키/장치 토큰을 넣지 않는다.
- 섞지 않을 것: PC 프로그램의 OpenAI SDK 호출, 기존 그래프/문서의 작업 큐 연결, 다중 장치 부하 분산, 공용 서버 키 대체.
- 선행 작업: 2. 설정·Google 접근의 공통 파일 변경을 먼저 반영한다.
- 하는 사람: Codex.

## 4. 개인 PC 실행 프로그램과 기존 AI 호출 연결

- 할 일:
  - 1절의 실행/작업 계약과 3절의 API를 읽고, 본인 `.env`의 `OPENAI_API_KEY`와 장치 자격증명으로 시작하는 실행 명령을 제공한다. 서비스 URL·본인 연결 대상을 PC에서 확인하며 HTTPS 인증서 검증을 유지한다.
  - 허용한 서비스·프롬프트/스키마 버전만 처리하고 본인이 정한 모델·출력 토큰·요청 빈도·동시 작업 상한을 PC에서 강제한다. 서버가 제공한 코드·모듈·URL을 실행하거나 .env 파일/키를 업로드하지 않는다.
  - 기존 구조화 출력·검증·오류 분류를 재사용해 PC에서 OpenAI를 호출하고 결과/안전한 오류만 제출한다. 키·인증 헤더·SDK 응답 원문은 서버, 로그, 메일·문서 결과에 보내지 않는다.
  - `local_worker`를 선택한 본인 메일 분석·답장·거래 추출·요약·성찰과 네 문서 `/extract`가 서버 사용자 키 대신 작업 큐 어댑터를 사용하게 한다. `stored_key` 모드는 기존 동작을 유지한다.
  - 작업 대기와 외부 API 호출의 전체 기한을 제한하고 재시도 책임을 한곳에 둬 서버·프로그램의 중복 재시도를 피한다. PC 오프라인·프로그램 종료·연결 해제·버전 불일치·키 거부·시간 초과를 화면/API에 구분해 안내한다.
  - 미완료·기한 지난 결과로 후보/문서가 생성되지 않게 하고, 연결 해제 이후 도착한 결과도 거부한다. 수동 문서 작성·검토·파일 발급, 메일의 사용자 승인 후 발송은 유지한다.

## 5. 실제 환경에서 두 방식 사용 확인

- 할 일:
  - 1~4절 병합과 필수 검사 통과 뒤 운영 DB를 백업하고 Render 배포·마이그레이션을 확인한다. 기존 `TOKEN_ENCRYPTION_KEY`·OAuth·Pub/Sub 설정은 유지하고 공용 Render의 환경 키 사용은 계속 금지한다.
  - 로컬 전체 실행은 개인 PC의 별도 DB와 본인 OAuth 설정·본인 .env 키로 확인한다. 운영 DB/암호화 키·OAuth 비밀값을 개인 PC에 복사하지 않는다.
  - Render + 개인 실행 프로그램은 두 사용자·두 PC로 각각 연결하고, 가상 메일 후보 생성과 네 문서 추출을 각자 프로젝트 사용량과 함께 확인한다.
  - 프로그램 중지/재시작·키 삭제/교체·연결 해제·서버 재시작·인터넷 단절 시 안내와 처리 결과, 로컬 Gmail 수집의 공용 감시 비간섭을 확인한다.
  - 실제 키·토큰·개인정보 없이 결과를 `docs/test-records/`에 기록한다. 실패하면 해당 구현 Issue를 다시 열어 원인과 재현 조건을 남긴다.
- 완료 기준: 기존 서버 등록·로컬 전체 실행·Render + 개인 실행 프로그램의 정상/오류 결과, 각 키의 과금 프로젝트, 키가 공용 서버로 전송/저장되지 않는 시험 근거와 사용 안내가 기록된다. 미확인 항목을 완료로 표시하지 않는다.
- 영향받는 상태·도구·노드: 운영 배포·DB 마이그레이션·Google 콘솔과 개인 PC 실행 환경. 코드 변경이 필요하면 해당 구현 작업으로 돌린다.
- 섞지 않을 것: Codex에 실제 키 입력, 실제 개인/업무 메일 사용, 확인 전 전체 사용자 전환, 자동 병합.
