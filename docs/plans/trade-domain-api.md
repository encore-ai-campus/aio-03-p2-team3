## 1. 기본 오류와 저장 일관성 (완료)
- 할 일: 기존 SQLite/Postgres 스키마의 데이터 보존 갱신, 수정 시 가격 재검증, 문서 버전과 조건부 갱신, 발송 중 수정 차단을 구현한다.
- 완료 기준: 이전 DB의 사용자·가격·후보 데이터가 유지되고 새 ORM으로 조회 가능하다. 통화·상품 변경 후 이전 가격 인증이 남지 않는다. PDF 준비 중 수정되거나 발송 중 수정하는 요청이 차단된다. 전체 회귀 시험 통과.
- 영향받는 상태·도구·노드: `TradeDocument`·DB 초기화·무역 수정/발송 서비스. 그래프의 노드·전이는 유지한다.
- 섞지 않을 것: 새 화면, 실제 발송, 마스터 챗봇.
- 선행 작업: 없음.
- 하는 사람: Codex.

## 2. PI 독립 업무 모듈 (완료)
- 할 일: `trade/pi`에 입력/출력 모델·업무·LangChain 진입점·저장소를 분리한다. 계산·가격·출력 함수는 재사용하고 DB/AI 의존성을 주입한다.
- 완료 기준: PI를 기존 메일 그래프 없이 생성·수정·검증할 수 있다. 직접 입력과 가짜 AI 추출의 같은 데이터가 같은 결과를 만든다. 업무 코드가 구체 DB나 FastAPI에 의존하지 않는다.
- 영향받는 상태·도구·노드: PI 입력·출력과 저장소 인터페이스, 기존 무역 생성 어댑터.
- 섞지 않을 것: 범용 에이전트 기반 클래스, 별도 서버, LLM 공급자 변경.
- 선행 작업: 1.
- 하는 사람: Codex.

## 3. React용 PI API와 검토 제안 (완료)
- 할 일: 인증된 JSON API로 작성·조회·수정·검토·승인·취소·다운로드를 연결한다. 불변 제안·문서 버전·선택 기록·생성 파일을 저장하고 승인과 메일 발송을 분리한다.
- 완료 기준: 실제 ASGI API를 통한 전체 흐름 시험 통과. 취소 시 파일 미발급, 수정 시 이전 제안 무효화, 오래된/중복 승인·다른 사용자 접근 거부, 재시도 시 파일 중복 발급 없음. PDF/XLSX 다운로드가 승인된 버전과 일치한다.
- 영향받는 상태·도구·노드: 문서 버전·검토 제안·선택 기록·파일 표, `trade/review`, PI router. 공통 업무 결과 형식은 문서 ID·버전·처리 상태·누락 항목·제안·파일 참조를 사용한다.
- 섞지 않을 것: React 화면 구현, 메일 발송을 포함한 문서 승인, 마스터 그래프.
- 선행 작업: 2.
- 하는 사람: Codex.

## 4. PO·CI·PL 모듈과 API
- 할 일: PI와 같은 경계로 PO·CI·PL을 분리한다. PO 매입가격, CI 원본 PI 버전/가격 보존, PL 단위별 포장 합계와 명시적 수정 확인을 보존한다.
- 완료 기준: 네 문서의 독립 모듈·AI 진입점·인증 API·검토/선택/파일 흐름이 모두 실제 요청 시험으로 확인된다. 공통 구현에 문서별 가격/포장 정책이 섞이지 않는다. 기존 전체 시험과 규칙 검사 통과.
- 영향받는 상태·도구·노드: `trade/po`·`trade/ci`·`trade/pl`, 문서별 router와 기존 생성 어댑터. 마스터 연결 없이 같은 공통 결과 형식을 반환한다.
- 섞지 않을 것: 마스터 챗봇, 계약서, Streamlit, 프런트엔드 개편.
- 선행 작업: 3.
- 하는 사람: Codex.
