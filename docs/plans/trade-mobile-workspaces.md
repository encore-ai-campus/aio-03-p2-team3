### 1절 구현 결과와 뒤 절의 재사용 규칙

- `frontend/src/styles.css`의 `--mobile-nav-height`는 `63px + env(safe-area-inset-bottom,0px)`이다. 800px 이하에서 `.bottom-nav` 전체 높이, `.shell` 아래 여백, `.pi-step-actions`와 `.review-panel > .form-actions`·`.pi-question > .form-actions`의 sticky `bottom`이 이 값을 함께 사용한다. 하단 메뉴는 최소 44px 터치 영역을 두고 문서 작업 버튼은 줄바꿈한다. `html`의 아래 scroll-padding은 탐색 높이+110px로 포커스 이동 시 여유를 둔다.
- 기존 600/800/1100px 전환을 유지한다. 600px 이하의 `.pi-item-table`은 같은 입력 DOM을 카드로 배치하고 `.pi-summary dl`은 한 열이다. 긴 값/오류/검토 제목은 줄바꿈하고 select는 부모 폭 안에 둔다. 크기 변경을 감지해 폼을 재생성하거나 단계를 바꾸지 않는다. PI/PO의 입력·단계·펼친 요약·포커스와 품목 상세가 크기 변경 중 유지된다.
- `DocumentSnapshot.jsx`의 `.table-scroll`은 이름을 가진 `region`과 `tabIndex=0`으로 키보드 스크롤에 접근한다. 전체 본문 대신 이 영역 안에서 넓은 금액 표를 스크롤한다. `:focus-visible`을 유지하며 단계 제목의 outline 숨김을 제거했다.
- PI/PO 페이지는 `AIInput`의 기존 `value`/`onTextChange`를 사용해 원문을 부모에 보존한다. 작성 방법 왕복·크기 변경 시 원문이 남고 새 문서 경로에서는 초기화된다. API 오류는 `tabIndex=-1`의 alert로 포커스를 옮긴다. 409에서 draft/현재 단계는 그대로 두고 최신본 읽기가 입력을 교체한다는 기존 안내를 유지한다. 다운로드 실패 뒤 busy가 풀리면 같은 파일 버튼으로 재시도한다.
- 재검증: `uv run pytest tests/test_trade_mobile_browser.py -q`. 실제 FastAPI·임시 pgvector PostgreSQL·가짜 인증/추출/Storage와 빌드한 React를 사용한다. 390px 완주, 320/768/1440px 입력/검토/발급 배치, 390→1440→390px 상태, 34px 하단 여유 모의, Tab/포커스, 실제 409와 다운로드 실패/재시도 해시를 확인한다. 상세 수치·환경·미확인은 [기존 검증 기록](../test-records/20261113_po_ci_pl_screens.md#issue-208-pipo-모바일-보완2026-11-17)에 있다. 뒤 절은 같은 클래스와 검증 방식을 재사용하되 CI/PL 업무 완주는 별도로 검사한다.

### 각 절의 공통 검증과 완료 기록

- 실제 FastAPI·임시 pgvector PostgreSQL·가짜 인증/Storage/OpenAI와 합성 자료를 사용한다. 실제 사용자 키/문서·Google 동의·유료 호출·운영 배포를 요구하지 않는다. 수동 직접 작성은 AI 키 없이 가능해야 한다.
- `python3 .work/check.py`, 전체 `uv run pytest`, `frontend/`의 `npm test`, `npm run lint`, `npm run build`, `npm run check:env`와 `git diff --check`를 실행한다. 새 자동 검사는 입력 보존·중복 승인·버전 충돌처럼 실제 회귀 위험에만 추가하고 스타일별 snapshot을 늘리지 않는다.
- 브라우저 완주는 390px에서 수행하고 320px(소형 모바일)·768px(태블릿)·1440px(데스크톱)은 배치와 주요 동작을 회귀 확인한다. 이미 통과한 업무 시나리오는 크기별로 전부 반복하지 않되 크기 변경으로 결함이 생기면 해당 경로를 다시 확인한다. `document.documentElement.scrollWidth`와 `clientWidth`로 본문 넘침을 측정하며, 전체 문서/원본 대조 표의 내부 스크롤은 허용하되 영역 이름·접근/이동 방법을 제공한다. 긴 문자열과 복수 품목/포장 행도 포함한다.
- 입력·이전/다음·요약·검토/취소·다운로드를 Tab/Enter로 조작하고 포커스·오류 안내를 확인한다. 터치로 쓰는 주요 동작은 44px 크기를 기준으로 한다. 하단 safe-area와 가상 키보드는 제공 가능한 브라우저/기기에서 확인하고, DOM 크기 축소만으로 실제 기기 키보드 확인을 대신하지 않는다. 실제 기기를 쓰지 못했다면 그 범위를 미확인으로 적는다.
- `docs/test-records/20261113_po_ci_pl_screens.md`에 기준 커밋·브라우저/너비·정상/오류 입력·관찰 결과·발급 해시·미확인 범위를 남긴다. 선행 기록은 보존하고 실제 재현한 결함과 확인 후보를 구분한다. 각 절 완료 뒤 제목에 `(완료)`를 붙이고 작업표를 갱신한다.
